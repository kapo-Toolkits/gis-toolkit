# GDB/MDB → PostGIS — სრული ინსტრუქცია

GIS_BOX-ის **„GDB → PostGIS"** ხელსაწყოთი: პირველადი ჩატვირთვა Geodatabase-იდან,
შემდეგ მხოლოდ ცვლილებების პერიოდული ატანა PostgreSQL/PostGIS-ში, ავტომატიზაცია
და ოპტიმიზაცია.

---

## 0. წინაპირობა

| საჭიროა | დეტალი |
|---|---|
| **GDAL** | `ogr2ogr`/`ogrinfo` — მოყვება **QGIS**-ს ან **OSGeo4W**-ს. ხელსაწყო თავად პოულობს. |
| **PostgreSQL + PostGIS** | ხელმისაწვდომი ბაზა, სადაც `CREATE EXTENSION postgis;` შესრულებულია. |
| **წყარო** | ESRI File Geodatabase (`.gdb`) ან Personal Geodatabase (`.mdb`). |

GIS_BOX-ში მარცხენა მენიუდან აირჩიე **„GDB → PostGIS"**. ფანჯარა სქროლადია — ქვემოთ
ყველა სექციამდე ჩამოსქროლ.

---

## 1. GDAL — შემოწმება (ერთხელ)

- ზედა ველი **„GDAL (ogr2ogr)"** — ჩვეულებრივ ცარიელი; გვერდით ჩანს **„ნაპოვნია — GDAL x.y"**.
- თუ წერია **„ვერ მოიძებნა"** → **„დათვალიერება…"**-ით მიუთითე `ogr2ogr.exe`
  (მაგ. `C:\Program Files\QGIS 4.0.0\bin\ogr2ogr.exe`).

---

## 2. წყარო და შრეები

1. **„წყარო საქაღალდე"** → **„დათვალიერება…"** — მიუთითე საქაღალდე, სადაც `.gdb`/`.mdb`-ია.
2. **„წყარო (.gdb/.mdb)"** ჩამოსაშლელი — აირჩიე ბაზა.
3. **„შრეები (მონიშნე ასატანი)"** — მონიშნე საჭირო შრეები:
   - რამდენიმე — `Ctrl`/`Shift`-ით, ან ღილაკი **„ყველა"** / **„არცერთი"**.

---

## 3. PostGIS კავშირი

შეავსე **„PostGIS კავშირი"** სექცია:

| ველი | მაგალითი |
|---|---|
| ჰოსტი | `localhost` |
| პორტი | `5432` |
| ბაზა | `test` |
| მომხმარებელი | `postgres` |
| პაროლი | `••••••` |
| სქემა | `public` |

- **„კავშირის შემოწმება"** — დააჭირე; უნდა გამოვიდეს „კავშირი წარმატებულია".
- **„პაროლის დამახსოვრება (ლოკალურად)"** — მონიშნე მხოლოდ თუ ავტომატიზაცია გინდა
  (ფონური გაშვება პაროლს საჭიროებს). ინახება ლოკალურად, კოდში/რეპოში არასდროს.

## 4. ეტაპი A — პირველადი ჩატვირთვა (baseline)

**„პარამეტრები" სექცია:**

| პარამეტრი | პირველ ჯერზე |
|---|---|
| **რეჟიმი** | **`overwrite`** ✅ |
| **რეპროექცია** | ცარიელი (თუ SRID-ს არ ცვლი) ან `EPSG:xxxx` |
| **ცხრილის პრეფიქსი** | ცარიელი (ან მაგ. `src_`) |
| **Promote to multi** | ☑ (რეკომ.) |
| **სივრცული ინდექსი (GiST)** | ☑ (რეკომ.) |
| **სწრაფი COPY** | ☑ (სწრაფია) |

➡️ დააჭირე **▶ იმპორტი**.

> **რატომ `overwrite`?** ის თავიდან ქმნის ცხრილს **სწორი SRID-ითა და სქემით**.
> **`append` არ გამოიყენო პირველ ჯერზე** — ის მხოლოდ არსებულ, **ზუსტად თავსებად**
> ცხრილს ამატებს რიგებს; შეუთავსებელ ცხრილზე მოგცემს შეცდომას
> `ERROR 1: Transaction not established` (იხ. [ხარვეზები](#8-ხშირი-ხარვეზები)).

---

## 5. ეტაპი B — მხოლოდ ცვლილებები (ინკრემენტული)

baseline-ის შემდეგ, იმავე შრეებში ცვლილებების ასატანად:

**„ინკრემენტული სინქრონი" სექცია:**

1. **☑ ინკრემენტული (მხოლოდ ცვლილებები)** — მონიშნე.
2. მონიშნე **ერთი შრე** და დააჭირე **„ველების ავტო-აღმოჩენა"** — შეავსებს:
   - **key ველი** — უნიკალური ID (`OBJECTID` / `GlobalID`),
   - **ცვლილების ველი** — ცვლილების თარიღი (`last_edited_date`).
   - თუ ვერ იპოვა — ჩაწერე ხელით.
3. **☑ წაშლილების დეტექცია** — მონიშნე, თუ წყაროში წაშლილი ობიექტები
   PostGIS-იდანაც უნდა მოცილდეს.

➡️ **▶ იმპორტი**.

**როგორ მუშაობს:**
- **პირველი** ინკრემენტული გაშვება = სრული load + **watermark** (ცვლილების ველის მაქს.).
- **შემდეგ** = მხოლოდ `ცვლილების ველი > watermark` რიგები, **upsert**-ით
  (შეცვლილი — ადგილზე განახლდება key-ით, ახალი — დაემატება).

> ⚠️ ვინაიდან ეტაპ A-ზე `overwrite` გამოიყენე (watermark-ის გარეშე), **პირველი**
> ინკრემენტული გაშვება ერთხელ კიდევ სრულად გადატვირთავს (staging-swap, ტრანზაქციული),
> მერე უკვე მხოლოდ ცვლილებები ადის.

> ❗ **`append` ≠ ინკრემენტული.** `append` ყოველ ჯერზე იმავე ობიექტებს თავიდან ამატებს
> (დუბლიკატები). „მხოლოდ ცვლილებებისთვის" **ყოველთვის ინკრემენტული** გამოიყენე.

## 6. ეტაპი C — ავტომატიზაცია

რომ ცვლილებები თავისით ადიოდეს პერიოდულად:

1. **💾 პარამეტრების დამახსოვრება** — ინახავს ბაზას, **მონიშნულ შრეებს**, კავშირს,
   რეჟიმსა და ინკრემენტულ პარამეტრებს (რომ თავიდან არ მიუთითო).
2. **„განრიგი" სექცია:** ☑ „ავტომატურად ყოველ **N წუთი/საათი/დღე**" → **„გამოყენება"**.
   - ჩანს **„შემდეგი გაშვება: …"**. მუშაობს **სანამ GIS_BOX ღიაა**.
3. **GIS_BOX-ის დახურვის შემდეგაც** (Windows):
   - მონიშნე **☑ „GIS_BOX-ის დახურვის შემდეგაც (Windows Task Scheduler)"** → **„გამოყენება"**.
   - რეგისტრირდება Windows-ის დავალება **`GIS_BOX_gdb2postgis`** — უფანჯროდ უშვებს იმპორტს.
   - საჭიროა **შენახული პაროლი** (ან garemos ცვლადი `PGPASSWORD`).
   - ჩართვისას მიმდინარე არჩევანი **ავტომატურად ინახება**.
   - გამორთვისას (თოლია მოხსენი ან განრიგი გამორთე) → დავალება **იშლება**.
   - ლოგი: **`gdb2postgis_run.log`** (GIS_BOX-ის საქაღალდეში).

## 7. ისტორია / აუდიტი

**🕘 ისტორია…** — ხსნის ფანჯარას:
- აირჩიე **თარიღი** → იმ დღის გაშვებები (შრე, რეჟიმი, რამდენი შეხებული/წაშლილი, ok).

- **„ამ ობიექტების წაშლა ბაზიდან"** — არჩეული გაშვების ობიექტებს შლის PostGIS-იდან.
- **„ამ ჩანაწერის წაშლა"** — ისტორიის ჩანაწერს აშორებს.

## 8. ხშირი ხარვეზები

### `ERROR 1: Transaction not established`
`append`-ის დროს პირველივე რიგი PostgreSQL-მა უარყო → ტრანზაქცია ჩაიშალა.
- **მიზეზი:** სამიზნე ცხრილი უკვე არსებობს **შეუთავსებელი** განსაზღვრებით —
  ხშირად **სხვა SRID** ან გეომეტრიის ტიპი.
- **ნამდვილი შეცდომის სანახავად:** გამორთე **☑ „სწრაფი COPY"** და გაუშვი — GDAL
  აჩვენებს ნამდვილ მიზეზს „transaction not established"-ის ნაცვლად.
- **გამოსწორება:** ახალ/გაფუჭებულ ბაზაში ჯერ **`overwrite`** (ცხრილს სწორად შექმნის),
  მერე `append`/ინკრემენტული.

### SRID არ ემთხვევა
წყაროს SRID (მაგ. `32638` = UTM 38N) ≠ ცხრილის geom-სვეტის SRID.
- გამოსავალი: **`overwrite`** (ხელახლა შექმნის სწორი SRID-ით), ან **რეპროექცია**
  (`EPSG:xxxx`) რომ წყარო სამიზნის SRID-ზე გადაიყვანო.

### ფონური გაშვება ვერ დამოწმდა
- **☑ „პაროლის დამახსოვრება"** ან garemos ცვლადი `PGPASSWORD`.

## 9. ოპტიმიზაცია — რჩევები

- **მუდმივი განახლებისთვის → ინკრემენტული**, არა `overwrite`/`append`.
  overwrite ყოველ ჯერზე მთელს ტვირთავს; ინკრემენტული — მხოლოდ ცვლილებას.
- **☑ სწრაფი COPY (PG_USE_COPY)** — ჩართე მასიური load-ისთვის (გაცილებით სწრაფია);
  დიაგნოსტიკისას დროებით გამორთე, რომ ნამდვილი შეცდომა დაინახო.
- **☑ სივრცული ინდექსი (GiST)** — დატოვე ჩართული; მოთხოვნები აჩქარდება.
  overwrite ინდექსს თავიდან ქმნის.
- **☑ Promote to multi** — ერევა Point/MultiPoint შერევის ტიპურ პრობლემას.
- **key + change ველი** — რაც უფრო ზუსტია (indexed `OBJECTID` + `last_edited_date`),
  მით სწრაფია ინკრემენტული (ნაკლები რიგი მოწმდება).
- **staging-swap** (overwrite-ის ავტომატური ქცევა) — მომხმარებელი ცარიელ/ნახევრად
  ჩატვირთულ ცხრილს ვერ ნახავს; გაშვება ატომურია.
- **პრეფიქსი** — თუ რამდენიმე წყაროდან ერთ ბაზაში ატან, `src1_`, `src2_` პრეფიქსით
  სახელების კონფლიქტს აირიდებ.
- **განრიგის ინტერვალი** — ბაზის დატვირთვის მიხედვით; ხშირ ცვლილებაზე წუთები,
  იშვიათზე — საათები.

## 10. მოკლე რეცეპტი

```
1. GDAL ✓  →  წყარო + შრეები  →  კავშირი („შემოწმება“)
2. რეჟიმი = overwrite  →  ▶ იმპორტი            (baseline)
3. ☑ ინკრემენტული  →  „ველების ავტო-აღმოჩენა“   (key + change)
   (სურვ.) ☑ წაშლილების დეტექცია
4. 💾 დამახსოვრება  →  ☑ განრიგი N  →  „გამოყენება“
   (სურვ.) ☑ „დახურვის შემდეგაც“ + შენახული პაროლი
5. კონტროლი: 🕘 ისტორია
```
